# Git: сохранить версию и вернуться к ней

Git хранит историю исходников на ПК. GitHub хранит её удалённую копию. Для этого проекта выбрана приватная видимость: **Private** в личном аккаунте без приглашённых участников.

Открой терминал в папке проекта:

```powershell
Set-Location D:\progr\projects\balance_app
```

## Сохранить изменения

```powershell
git status
git diff
git add .
git diff --cached --stat
git commit -m "Кратко описать сделанное изменение"
```

Коммит сохраняет только добавленные в него файлы. Перед коммитом проверь список: SDK, APK, build, кэши и ключи не должны попадать в историю. `pubspec.lock` сохраняется, чтобы фиксировать версии зависимостей.

## Посмотреть историю и старую версию

```powershell
git log --oneline --decorate -10
git show HEAD
git show baseline-skeleton:lib/main.dart
```

`baseline-skeleton` — метка первой сохранённой версии. Метка создаётся после начального коммита.

## Работать над новой функцией отдельно

```powershell
git switch -c feature/manual-input
```

Коммиты этой ветки сохраняют работу отдельно от `main`. Для возврата к основной ветке сначала сохрани текущую работу коммитом или stash, затем выполни `git switch main`.

## Открыть первую версию, сохранив новую историю

Сначала проверь `git status`. Если есть незакоммиченные изменения, сохрани их коммитом или временно:

```powershell
git stash push -u -m "Перед просмотром первой версии"
git switch -c inspect-baseline baseline-skeleton
```

Будет создана отдельная ветка на первой версии, а новая история останется на прежней ветке. Вернуться:

```powershell
git switch main
```

Если перед этим делал stash, посмотри `git stash list` и восстанови нужный через `git stash apply`. После проверки можно удалить именно этот stash. Stash с `-u` сохраняет неотслеживаемые файлы, но не файлы, исключённые .gitignore.

## Отменить уже сохранённое изменение

Найди нужный коммит в `git log`. Вместо HASH ниже подставь его короткий идентификатор:

```powershell
git revert HASH
```

Эта команда создаёт новый коммит отмены и сохраняет историю. При конфликтах нужно разобраться в файлах; для отказа от незавершённой отмены используется `git revert --abort`.

Не используй `git reset --hard` или `git clean` для обычного возврата: они могут удалить несохранённую работу. Откат исходников не откатывает базу данных приложения на телефоне — миграции проверяются отдельно.

## GitHub: email и приватный репозиторий

Автор проекта — SHAIINARK. Используется предоставленный им адрес `202836777+SHAIINARK@users.noreply.github.com` только в локальной конфигурации этой папки.

Noreply — адрес, предоставленный GitHub для авторства коммитов вместо личной почты. Он доступен в [Settings → Emails](https://github.com/settings/emails), после включения **Keep my email addresses private**. Его не нужно придумывать; нужно копировать из своего аккаунта. [Документация GitHub](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address).

Если репозиторий ещё не создан:

1. Открой [создание приватного репозитория balance_app](https://github.com/new?name=balance_app&visibility=private).
2. Выбери личный аккаунт владельцем и проверь **Private**.
3. Не создавай дополнительные README, .gitignore или лицензию: файлы уже есть локально.
4. Создай репозиторий и скопируй его HTTPS-адрес.

Вместо REPOSITORY_URL подставь адрес, показанный GitHub:

```powershell
git remote add origin REPOSITORY_URL
git remote -v
git push -u origin main
git push origin baseline-skeleton
```

GitHub может попросить вход. Пароль аккаунта не вставляй в команды; используй доступный вход через браузер/GitHub CLI или настроенный менеджер учётных данных. Токены не записывай в файлы проекта.

После настройки очередная отправка сохранённых версий:

```powershell
git push
```

Проверяй Private-видимость в GitHub и не приглашай участников, пока нужен доступ только тебе. [Создание репозитория: официальная инструкция](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository).

## Что сохраняется

В Git: исходники, Android/iOS-конфигурация без машинных путей, ресурсы, тесты, pubspec.lock и документация.

Вне Git: инструменты D:\dev-tools, build/APK, локальные свойства SDK, IDE-кэши, ключи подписи, личные банковские изображения. Ключи подписи будущих релизов требуют отдельной защищённой резервной копии.
