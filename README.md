# Кэшбэк рядом

Flutter-приложение на русском для Альфы, Т-Банка, Сбера, ВТБ и Ozon Банка. Версия **0.3.0+3 — ручные карты и категории с локальным хранением**.

Полный контекст и следующие промпты: [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md). Правила разработки: [AGENTS.md](AGENTS.md). Откат версий: [GIT_GUIDE.md](GIT_GUIDE.md). Исходники: [приватный GitHub](https://github.com/SHAIINARK/cashback-upp).

## Что работает

- Русская тема, навигация, пустые состояния, три соседних месяца на главной.
- Главная: просмотр категорий по убыванию процентов и режим просмотра по карте.
- Модели карт и категорий: точное название, процент, период, вид вознаграждения, примечания.
- Выбор до 10 скриншотов, временные приватные копии и очистка после просмотра.
- Локальный Android OCR русского/английского текста с моделями внутри APK.
- Банковский разбор, экран проверки с исходником, результатами, сменой банка и предупреждениями.
- Проверка импорта: переход к любому выбранному скриншоту, кнопки «Назад»/«Далее» при нескольких изображениях, выбор банка через отдельную панель с поиском и свободным вводом.

Ручные карты и категории сохраняются на телефоне и показываются на главной для выбранного месяца. OCR-результаты пока остаются черновиком и не сохраняются: их редактирование и явное подтверждение — отдельный следующий шаг. Галочки Т-Банка не распознаются; видимые предложения обозначены кандидатами. Бонусы Спасибо не приравниваются к рублям, категории банков не объединяются.

## Запуск на Windows

Инструменты находятся в D:\dev-tools. Нужны PUB_CACHE, GRADLE_USER_HOME, ANDROID_HOME, ANDROID_USER_HOME и JAVA_HOME, указывающие на соответствующие каталоги D:\dev-tools.

```powershell
flutter pub get
flutter analyze
flutter test
flutter run -d RF8T1051S0V
flutter build apk --debug
```

APK: `build/app/outputs/flutter-apk/app-debug.apk`. Это отладочная сборка, не пакет для магазина. Tesseract4Android загружается из JitPack при сборке; распознавание после установки не требует сети. Сетевые разрешения debug нужны инструментам Flutter.

## Структура и проверка

`lib/domain` — модели и независимый контракт OCR; `lib/data` — нативный адаптер и репозиторий; `lib/logic` — контроллер импорта и отдельные банковские правила; `lib/presentation` — интерфейс; `android`/`ios` — платформенные движки. Пользовательская база не зависит от формата OCR.

[Результаты реальных измерений](docs/OCR_RESULTS.md), [исследование движков](docs/OCR_ENGINE_RESEARCH.md), [происхождение моделей](docs/ocr-models.json).

Для повторения измерений нужны пять оригиналов из раздела 6 PROJECT_CONTEXT.md и подключённый отладочный телефон:

```powershell
$env:OCR_DEVICE='RF8T1051S0V'
flutter drive --driver=test_driver/ocr_driver.dart --target=integration_test/ocr_benchmark_test.dart -d RF8T1051S0V
```

Драйвер передаёт реальные изображения в приватные файлы тестового приложения, проверяет копии и удаляет их после теста. Отчёт и снимок интерфейса сохраняются в игнорируемой `private-data`. Не добавлять их в Git. Тест может переустановить приложение и очистить его данные; использовать тестовый телефон/установку. После него пересобрать обычный APK без тестового target.

## iOS и следующие этапы

Создан локальный адаптер Apple Vision с проверкой доступности русского языка и разрешением на фотографии. Без macOS/Xcode сборка и запуск iOS **не проверены**.

Далее: редактирование и явное подтверждение OCR-импорта, проверка выбранности, расширение набора реальных экранов и тест на iPhone. Локальный формат хранения имеет версию 1; при неизвестной версии файл не перезаписывается. До публикации определить окончательные идентификаторы, подпись и лицензии зависимостей. Сервер, регистрация, аналитика и монетизация не подключены.
